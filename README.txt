蔵書とノートの図書室 — GitHub Pages用

【公開】
1. ZIPを展開してください。
2. GitHubでBookshelfなどのリポジトリを作成します。
3. index.html、style.css、app.jsを同じ階層にアップロードします。
   フォルダごとではなく、中のファイルをアップロードすると簡単です。
4. Settings → Pages → Deploy from a branch → main / (root) → Save。
5. 公開URLの例：https://numumac.github.io/Bookshelf/
6. マイポータルに上記URLへの「蔵書管理」リンクを追加してください。
   この一式は既存のポータルファイル自体を変更しません。

【戻りリンク】
初期設定は https://numumac.github.io/ です。
実際のマイポータルが別URLの場合は「ポータル設定」から変更できます。
恒久的な初期値はindex.htmlのid="portal"のhrefで変更してください。

【登録】
書名、著者、分類、タグ、形態、読書状態、出版社、発行年、ISBN、巻・版、
保存場所、共有URL、評価、読了日、メモ、お気に入りを記録します。
共有URLはhttp/httpsのみ。iCloudの共有権限も別途必要です。
ファイル本体のアップロードやiCloudの自動スキャンは行いません。

【大量登録】
sample.csvの列名は変更しないでください。title（書名）は必須です。
他の列は空欄でも構いません。ExcelでCSV UTF-8として保存してください。
タグはカンマで区切り、そのセル全体を引用符で囲みます。
CSVにはIDを含めていないため、同じCSVを追加で再読み込みすると重複します。
sample.csvの2件は例です。自動登録はされません。

【保存とバックアップ】
データはIndexedDBで保存されます。1万件以上を想定していますが、
実際の上限は端末・ブラウザの保存容量に依存します。
公開サイトを開いた他の人にあなたの蔵書情報は共有されません。
同じ端末でもブラウザやサイトURLが変わると別の保存領域になります。
複数タブでの同時編集は避けてください。

JSONバックアップはIDと全項目を保存します。同じIDで再読み込みした場合、
追加モードでは更新します。置き換えモードでは既存の一覧をすべて置き換えます。
置き換え前に必ず現在のJSONを保存してください。
ポータル設定はJSONに含まれません。必要なら再設定してください。
CSVはExcel編集用です。数式として解釈される文字で始まる値は、
書き出し時に先頭にアポストロフィを付けます。忠実な復元にはJSONを使ってください。
読み込みファイルは50MBまでです。不正なファイルは全体を中止します。
端末間の移動：元の端末でJSON書き出し → 別端末の同じサイトで読み込み。
ブラウザのデータを削除する前、端末を交換する前、定期的な登録後にバックアップ。
HTMLファイルを直接開く方法より、GitHub Pagesでの利用を推奨します。

12,000件のデータ整形を確認しました。実ブラウザでの操作検証は未実施です。
